# Лабораторная работа 04 — CTC с нуля

## Цель
Получить практические навыки и понимание процесса вычисления CTC-loss.

## Ожидаемые результаты

После выполнения работы вы сможете:

- реализовать базовый алгоритм преобразования пути в итоговую расшифровку;
- реализовать часть алгоритма накопления оценок путей внутреннего выравнивания при вычилении CTC-loss;
- реализовать алгоритм жадного поиска.


## Что требуется сделать

Файлы в `scripts/` — исходный код для выполнения задания, а не готовые эталонные реализации. Некоторые строки с вычислениями намеренно заменены на `# напишите ваш код здесь`. **Дополните отмеченные выражения в существующих файлах.** Не заменяйте проект отдельной реализацией и не переписывайте окружающий код проверки входных данных, загрузки данных и т.д.

Наборы данных содержат фиксированные синтетические вероятности, а не реальные выходы.

### Что нужно дописать в коде

1. `merge_then_remove(path, blank)` (свёртка): объедините соседние одинаковые символы в исходном пути, затем удалите blank. `b b` превращается в `b`; `b blank b` — в `bb`. `sum_matching(records, target)` (агрегация): просуммируйте вероятности записей, соответствующих целевой транскрипции. Список токенов для алгоритма прямого прохода имеет алфавит `[blank,b,a]`, цель `ba`, три кадра, 27 путей и пять подходящих путей.
2. `incoming_sum(previous, extended, state, blank)` (входящая сумма): просуммируйте переходы с сохранением состояния `s`, переходом вперёд из `s-1` и пропуском из `s-2` только тогда, когда целевое состояние не является blank и отличается от `extended[s-2]`. Умножение на текущую эмиссию выполняйте вне этой функции. `terminal_sum(last_row)` (терминальная сумма): сложите два последних состояния либо единственное состояние для пустой цели. Расширенный таргет для `ba` выглядит как `[blank,b,blank,a,blank]`; Для `bb` прямой пропуск между одинаковыми токенами запрещён.
3. `greedy_path(emissions, alphabet)` (жадный поиск): выберите в каждом кадре токен с наибольшей вероятностью; при равенстве выбирайте по порядку в алфавите. `prefix_transitions(prefix, p_blank, p_nonblank, symbol, probability)` (префикс): если последний токен совпадает с текущим, накопленная вероятность, оканчивающаяся не на blank, остаётся у префикса, а накопленная вероятность, оканчивающаяся на blank, расширяет его (префикс); в противном случае обе накопленных вероятности расширяют префикс. Представленный код суммирует все переходы до отсечения. Накопленные вероятности путей, оканчивающихся на blank и не на blank, должны храниться раздельно. Накопленные вероятности луча ограниченной ширины могут быть приближёнными; жадный метод выбирает один путь, тогда как луч суммирует накопленные вероятности путей.
